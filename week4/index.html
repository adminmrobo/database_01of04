4주차의 학습 목표입니다. 아래 세부 페이지를 차례로 따라가면 자연스럽게 채워집니다. 전체 15주차 가운데 4주차입니다. 다음 주 주제는 정규화와 이상현상입니다.

  • 외부·개념·내부 스키마와 두 가지 사상을 그림으로 설명할 수 있다
  • 논리적·물리적 데이터 독립성을 구분하고 예를 들 수 있다
  • 개체·속성·관계를 찾아 ERD로 표현하고 릴레이션으로 옮길 수 있다
  • 키 다섯 종류와 두 가지 무결성 제약을 적용할 수 있다
  • 실무 프로젝트 흐름(설계 → 인덱스 → 장애 → 회고)을 설명할 수 있다

01DB 시스템

데이터베이스 시스템과 3단계 구조

데이터 사전, 사용자와 데이터베이스 언어, 외부·개념·내부 스키마와 두 사상, 그리고 데이터 독립성 애니메이션.

02데이터 모델링

데이터 모델링과 개체·속성·관계

현실 세계 → 개념 세계 → 컴퓨터 세계. 개체와 인스턴스, 속성의 여섯 갈래, 일대일·일대다·다대다 관계.

03ERD 실습

논리적 데이터 모델과 쇼핑몰 ERD

계층·네트워크·관계 모델을 비교하고, 쇼핑몰 ERD를 직접 그려 릴레이션으로 옮깁니다. 코드 가이드 4종 포함.

04관계 모델

관계 데이터 모델 — 릴레이션·키·무결성

릴레이션의 일곱 용어와 네 가지 특징, 키 다섯 종류, 개체 무결성과 참조 무결성. 위반 데이터를 실제로 넣어 봅니다.

05RPG 실무 사례

실무 프로젝트 — RPG 용사의 전설

파일 시스템의 한계를 겪은 게임 개발팀이 DBMS를 도입하고 캐릭터·아이템·전투·퀘스트를 설계하기까지, 열 단계 실무 기록.

✓정답

정답과 채점 기준

확인 문제 정답·해설·배점과 실습 모범 답안. 학습자는 문제를 먼저 푼 뒤에 여세요.

본문에서 점선 밑줄이 있는 낱말을 누르면 같은 비유가 그 자리에서 뜹니다. 여기서는 한꺼번에 훑어볼 수 있습니다.

3단계 구조

외부 스키마

비유같은 건물을 보는 창문. 창문마다 보이는 풍경이 다릅니다.

뜻사용자나 응용 프로그램이 필요로 하는 논리적 구조. 사용자 뷰의 집합입니다.

개념 스키마

비유건물의 도면. 모든 방과 연결 통로가 한 장에 그려져 있습니다.

뜻조직 전체 관점의 통합된 논리적 구조. 엔티티·속성·관계·제약을 정의합니다.

내부 스키마

비유벽 속의 배관과 전선. 보이지 않지만 건물이 서 있게 합니다.

뜻물리적 저장 구조의 정의 — 파일 구조, 인덱스, 접근 경로, 저장 영역.

사상 (Mapping)

비유통역사. 한쪽 이름이 바뀌어도 다른 쪽에는 같은 뜻으로 전달합니다.

뜻각 스키마 사이의 대응관계. 응용 인터페이스 역할을 합니다.

데이터 독립성

비유집 배관을 바꿔도 가구 배치는 그대로인 상태.

뜻한 스키마가 바뀌어도 다른 스키마·응용 프로그램이 영향을 받지 않는 성질. 논리적·물리적 두 가지가 있습니다.

데이터 사전

비유창고의 물품 대장. 물건 자체가 아니라 "무엇이 어디에 있는지"가 적혀 있습니다.

뜻스키마·사상 정보를 저장한 메타데이터. 시스템 카탈로그라고도 하며, 사용자는 접근만 가능합니다.

언어와 구성 요소

절차적 vs 비절차적

비유절차적은 "3번 국도로 가서 두 번째 신호에서 우회전", 비절차적은 "강남역으로 가 줘".

뜻절차적 조작어는 방법까지 지정하고, 비절차적 조작어(SQL)는 결과만 지정합니다.

질의처리기

비유주문을 받아 가장 빠른 동선으로 짜 주는 주방장.

뜻사용자의 데이터 처리 요구를 해석해서 처리하는 역할을 담당합니다.

저장데이터 관리자

비유창고 안에서 물건을 직접 꺼내 오는 사람.

뜻디스크에 저장된 데이터베이스와 데이터사전을 관리합니다.

개체와 속성

개체 (Entity)

비유서류함에 따로 보관할 만한 것. 이름표를 붙일 수 있고 여러 개가 있습니다.

뜻현실 세계에서 독립적으로 존재하는 대상. 개체 타입(틀)과 개체 인스턴스(실제 값)로 나뉩니다.

속성 (Attribute)

비유인물 카드에 적는 항목 — 이름, 나이, 주소.

뜻개체가 가지는 특성. 단순·복합·단일값·다중값·유도·키 속성으로 나뉩니다.

복합 속성

비유"주소"라고 적었지만 실제로는 시·구·동 세 칸입니다.

뜻여러 개의 단순 속성으로 나눌 수 있는 속성.

유도 속성

비유계산으로 나오는 값. 적어 두지 않아도 언제든 다시 계산할 수 있습니다.

뜻다른 속성 값에서 계산되는 속성(나이, 합계). ERD에서 점선 타원으로 표기합니다.

NULL값

비유빈칸과 0은 다릅니다. "모른다"와 "없다"도 다릅니다.

뜻값을 모르거나 적합한 값이 없는 경우를 표시하는 특별한 값.

관계와 모델

관계 (Relationship)

비유두 서류함 사이를 잇는 실. 그 실에 이름표와 값이 붙을 수 있습니다.

뜻개체와 개체 사이의 뜻 있는 연결. 1:1, 1:N, N:M으로 나뉘고 자체 속성을 가질 수 있습니다.

관계 유형 (카디널리티)

비유한 사람이 여러 장을 가질 수 있는지, 서로 여러 개인지.

뜻연결되는 개체 인스턴스의 수 관계. 1:1 / 1:N / N:M.

참여도

비유반드시 있어야 하는 참가자인지, 있어도 되고 없어도 되는지.

뜻전체 참여(모든 개체가 반드시 참여)와 부분 참여(일부만 참여)로 구분합니다.

ERD

비유건물을 짓기 전의 배치도. 아직 벽은 없지만 어디에 무엇이 놓일지 정해져 있습니다.

뜻개체-관계 다이어그램. 개체·속성·관계를 그림으로 표현한 개념적 구조.

릴레이션의 기본

릴레이션

비유칸이 정해진 장부. 행과 열이 있고, 같은 행이 두 번 나오면 안 됩니다.

뜻관계형 DB에서 정보를 구분해 저장하는 기본 단위. 행(투플)과 열(속성)이 있는 테이블.

튜플 · 속성

비유튜플은 장부의 한 줄, 속성은 장부의 한 칸 이름.

뜻튜플은 릴레이션의 행(개체 인스턴스·레코드), 속성은 릴레이션의 열(에트리뷰트).

도메인

비유칸에 들어갈 수 있는 값의 목록. "등급 칸에는 VIP·일반·휴면만".

뜻속성 하나가 가질 수 있는 모든 값의 집합. 속성의 특성을 고려한 데이터 타입으로 정의합니다.

차수 · 카디널리티

비유차수는 장부의 칸 수, 카디널리티는 장부에 적힌 줄 수.

뜻차수는 속성의 전체 개수, 카디널리티는 튜플의 전체 개수.

속성의 원자성

비유한 칸에 하나만. "010-1111 / 010-2222"처럼 두 개를 쓰면 그 칸은 셀 수 없습니다.

뜻릴레이션의 속성 값으로 원자 값만 사용할 수 있다는 특징.

키와 무결성

슈퍼키 · 후보키

비유슈퍼키는 "이름+전화번호+생일"처럼 과하게 많이 적은 명찰, 후보키는 딱 하나만 남긴 명찰.

뜻슈퍼키는 유일성만, 후보키는 유일성과 최소성을 모두 만족하는 속성 집합.

기본키 · 대체키

비유여러 명찰 중 대표로 고른 하나가 기본키, 나머지는 서랍에 넣어 둔 대체키.

뜻기본키는 후보키 중 선택된 하나, 대체키는 기본키로 선택되지 못한 후보키.

외래키

비유다른 장부를 가리키는 쪽지. 쪽지에 적힌 번호가 그 장부에 없으면 안 됩니다.

뜻어떤 릴레이션의 속성 또는 속성집합이 다른 릴레이션의 기본키가 되는 키.

개체 무결성

비유이름 없는 출입증은 출입증이 아닙니다.

뜻기본키를 구성하는 모든 속성은 NULL값을 가지면 안 된다는 제약.

참조 무결성

비유없는 사람에게 보내는 편지는 반송됩니다.

뜻외래키는 참조할 수 없는 값을 가질 수 없다는 제약. 단 NULL은 허용됩니다.

실무 설계

인덱스

비유책 뒤의 찾아보기. 본문을 다 넘기지 않고 바로 그 쪽으로 갑니다. 대신 책이 조금 두꺼워집니다.

뜻특정 열의 값을 빠르게 찾기 위한 별도 자료 구조. 조회는 빨라지고 쓰기·저장공간은 늘어납니다.

복합 인덱스

비유"성+이름" 순으로 정렬된 명부. 성만으로도 찾을 수 있지만 이름만으로는 못 찾습니다.

뜻두 개 이상의 열을 묶은 인덱스. 열 순서가 성능을 좌우합니다.

카디널리티 (선택도)

비유값의 종류가 많은 열일수록 잘 걸러집니다. "성별"보다 "주민번호"가 훨씬 잘 걸러집니다.

뜻열에 들어 있는 서로 다른 값의 개수. 인덱스 열 순서를 정할 때 기준이 됩니다.

비정규화

비유자주 쓰는 값을 손님이 보는 자리에 미리 놓아 두기. 정리는 덜 됐지만 빠릅니다.

뜻성능을 위해 의도적으로 중복을 남기는 설계. 이유를 반드시 기록해야 합니다.

샤딩

비유한 창고가 꽉 차서 월드별로 창고를 나누는 것.

뜻데이터를 여러 서버에 나눠 저장해 대규모 동시접속을 처리하는 전략.

파티셔닝

비유한 장부를 월별 권으로 나누기. 10월 자료를 볼 때 9월 권은 열지 않습니다.

뜻큰 테이블을 기간·범위 등으로 나눠 관리하는 기법. 조회 범위를 좁혀 성능을 올립니다.

채점 기준Scoring

문항당 2점입니다. 정답만 고른 학습자보다 이유를 말한 학습자를 더 높게 봅니다.

1문항당 배점
  • 2점 — 정답을 고르고, 그 이유를 해설의 핵심 논리로 한 문장 설명함
  • 1점 — 정답만 고름 (이유를 말하지 못함)
  • 1점 — 오답이지만 해설의 핵심 이유를 말함
  • 0점 — 무응답이거나, 오답이고 이유도 다른 개념을 가리킴
왜 오답에도 1점인가 — 이 자료의 확인 문제는 암기 시험이 아니라 설계 판단 훈련입니다. 근거를 말할 수 있으면 개념은 잡힌 것이므로 부분 점수를 줍니다.

✓ 확인 문제

01Q1. 롤백(Rollback)에 대한 설명으로 가장 알맞은 것은?

  • 데이터베이스를 백업 파일로 통째로 되돌리는 것
  • 업데이트 오류 시 저널 파일을 이용해 이전 상태로 되돌리는 것 ✔ 정답
  • 응용 프로그램을 이전 버전으로 되돌리는 것
해설 롤백은 업데이트에 오류가 발생했을 때 이전 상태로 되돌리는 것을 말하며, 이전의 저널 파일을 사용합니다. '앞으로 복구'는 회복(redo)의 영역입니다.
배점 2점 · 정답을 고르고 이유를 한 문장으로 말하면 2점, 정답만 고르면 1점, 오답이어도 해설의 핵심 이유를 말하면 1점.

02Q2. 다음 중 DBMS의 단점 에 해당하지 않는 것은?

  • 비용의 문제
  • 중앙관리로 인한 취약점
  • 데이터의 중복을 통제할 수 있음 ✔ 정답
해설 데이터의 중복을 '통제'하고 독립성을 확보하는 것이 DBMS의 장점입니다. 비용 증가, 백업·회복의 복잡성, 중앙관리로 인한 취약점은 단점입니다.
배점 2점 · 정답을 고르고 이유를 한 문장으로 말하면 2점, 정답만 고르면 1점, 오답이어도 해설의 핵심 이유를 말하면 1점.

03Q3. DBMS의 세 가지 주요 기능을 바르게 짝지은 것은?

  • 정의 · 조작 · 제어 ✔ 정답
  • 입력 · 출력 · 저장
  • 백업 · 복구 · 암호화
해설 정의(DDL)는 데이터 구조를 만들고, 조작(DML)은 값을 다루며, 제어(DCL)는 권한·무결성·동시성·회복을 관리합니다.
배점 2점 · 정답을 고르고 이유를 한 문장으로 말하면 2점, 정답만 고르면 1점, 오답이어도 해설의 핵심 이유를 말하면 1점.

04Q4. 1세대 계층형 DBMS의 가장 큰 한계는?

  • 다대다 관계를 표현할 수 없다 ✔ 정답
  • 데이터 접근이 너무 느리다
  • 트랜잭션을 지원하지 않는다
해설 계층형 DBMS는 부모-자식 트리 구조라 다대다 관계를 표현할 수 없습니다. 네트워크형이 그래프 구조로 이를 보완했습니다.
배점 2점 · 정답을 고르고 이유를 한 문장으로 말하면 2점, 정답만 고르면 1점, 오답이어도 해설의 핵심 이유를 말하면 1점.

05Q5. NoSQL의 특징으로 알맞은 것은?

  • 강한 일관성과 수직적 확장
  • 유연한 스키마와 수평적 확장 ✔ 정답
  • 2차원 표 형태의 데이터 저장
해설 NoSQL은 유연한 스키마와 수평적 확장성이 강점이지만, 일관성 모델(최종 일관성 등)을 상황에 맞게 선택해야 한다는 부담이 있습니다.
배점 2점 · 정답을 고르고 이유를 한 문장으로 말하면 2점, 정답만 고르면 1점, 오답이어도 해설의 핵심 이유를 말하면 1점.

06Q6. 트위터(X)가 데이터 특성에 맞게 여러 DB를 혼합 사용하는 전략을 부르는 말은?

  • 마이크로서비스 아키텍처
  • 샤딩 전략
  • 폴리글랏 퍼시스턴스 ✔ 정답
해설 트위터(X)는 데이터 특성에 맞춰 MongoDB·Redis·MySQL을 혼합 사용하는 폴리글랏 퍼시스턴스 전략을 씁니다. 실시간 피드는 NoSQL, 결제·인증은 RDBMS로 분리했습니다.
배점 2점 · 정답을 고르고 이유를 한 문장으로 말하면 2점, 정답만 고르면 1점, 오답이어도 해설의 핵심 이유를 말하면 1점.
실습

실습 과제 모범 답안Lab Notes

실습은 정답이 하나로 고정되지 않습니다. 아래는 설계 판단의 근거 중심의 채점 참고안입니다.

L23주차 실습 — 파일 시스템과 DBMS를 같은 업무로 비교하기

모범 답안 요점 — 같은 '고객 주소 변경' 업무를 파일 시스템과 DBMS 두 방식으로 적어 보고, 무엇이 달라지는지 정리합니다.
  • 파일 시스템 — 고객 파일, 주문 파일, 배송 파일에 주소가 흩어져 있으면 세 곳을 모두 찾아 고쳐야 합니다. 하나를 빠뜨리면 불일치가 생기고, 그 불일치를 찾는 비용이 계속 듭니다.
  • DBMS — 주소는 고객 테이블 한 곳에만 있고, 주문·배송은 고객번호를 참조합니다. 한 행만 고치면 끝나고, 참조 무결성이 어긋난 상태를 막아 줍니다.
  • 트랜잭션 — 변경 도중 실패하면 롤백으로 되돌립니다. 파일 시스템에서는 어디까지 반영됐는지 사람이 판단해야 합니다.
  • 동시 공유 — 두 사람이 같은 고객을 동시에 고칠 때 DBMS는 잠금과 동시성 제어로 순서를 정합니다.
채점 포인트 — "DBMS를 쓰면 편하다"는 결론만으로는 부족합니다. 중복·종속·동시 공유·보안·회복 다섯 문제 중 어느 것이 어떤 방식으로 해결되는지 짝지어 말해야 만점입니다.

오답이 몰리는 지점Common Mistakes

3주차에서 특히 자주 틀리는 곳입니다.

1중복의 '판단' 비용

중복 데이터가 나쁜 이유는 저장 공간이 아니라, 같은 값인지 판단하고 관리하는 프로세스가 계속 필요하기 때문입니다.

2위치 참조 ↔ 내용 참조

파일 번호·블록 주소로 찾으면 위치 참조, '이름이 김철수인 고객'처럼 값의 조건으로 찾으면 내용 참조입니다.

3롤백 ↔ 회복

롤백은 오류 시 저널 파일로 이전 상태로 되돌리는 것, 회복(redo)은 앞으로 복구하는 것입니다. 방향이 반대입니다.

4DBMS의 장점 ↔ 단점

'중복을 통제할 수 있다'는 장점, '비용 증가·백업 복잡·중앙관리 취약'은 단점입니다. 장단점을 뒤섞어 고르는 오답이 많습니다.

도입 문제 — 주소가 바뀌었습니다Problem

고객 김철수가 이사를 했습니다. 영업부, 마케팅부, 서비스부가 각자 고객 파일을 관리하고 있었다면 무슨 일이 벌어질까요?

가파일 시스템에서의 하루
09:00 영업부 고객정보.dat 주소 수정 ✓ 09:20 마케팅부 고객정보(복사).dat 주소 수정 ✓ 11:40 서비스부 고객정보_v2.xls 주소 수정 ✓ 13:00 재고관리 주문.xls 주소 수정 ✗ (누락) 15:00 택배 발송 → 옛 주소로 배송

같은 고객의 주소가 네 곳에 중복 저장되어 있고, 그중 하나를 빠뜨렸습니다. 이것이 데이터 중복 문제입니다.

나누가 잘못했나

담당자의 실수가 아닙니다. 구조가 그렇게 되어 있습니다. 중복 데이터를 관리하려면 "이 값이 다른 파일에도 있는지 판단하는 프로세스"와 "모두 고치는 관리 프로세스"가 필요한데, 파일 시스템은 그 둘을 대신해 주지 않습니다.

중복 데이터로 인한 문제 데이터베이스 구조 외에 다양한 요인(담당자, 시점, 복사본, 백업본)이 얽혀 있어, 사람이 전부 통제하는 것은 사실상 불가능합니다.

파일 시스템의 데이터 관리File System

데이터 관리의 출발점입니다. 파일 시스템이 나쁜 것이 아니라, 규모가 커지면 감당이 안 되는 것입니다.

1파일 시스템이란

컴퓨터에서 파일이나 자료를 체계적으로 관리하는 방법입니다. 운영체제와 데이터 사이의 인터페이스 역할을 하며, 디렉터리와 파일 단위로 데이터를 관리하고 물리적 저장 장치에 직접 매핑됩니다.

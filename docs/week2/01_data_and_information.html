도입 문제 — 영수증 한 장Problem

오늘 오후 3시 12분, 편의점에서 삼각김밥 2개와 커피 1잔을 샀습니다. 영수증에는 이런 값들이 찍혀 있습니다.

가영수증에 찍힌 것
2026-10-18 15:12:07 삼각김밥 1,400 × 2 아메리카노 1,800 × 1 합계 4,600 카드 ****-1234

날짜, 시각, 상품명, 단가, 수량, 합계, 카드번호 — 모두 현실에서 관찰하거나 측정해 수집한 값입니다. 이것이 데이터입니다.

나여기서 무엇을 알 수 있나
  • 오늘 오후 3시대 매출은 4,600원이다.
  • 삼각김밥이 커피보다 많이 팔렸다(2개 vs 1개).
  • 이 카드 사용자는 점심 직후에 편의점을 자주 온다.

이 세 문장은 영수증에 직접 적혀 있지 않습니다. 값들을 모으고, 세고, 비교해서 만들어 낸 결과입니다. 이것이 정보입니다.

다그래서 이 편의 질문

데이터와 정보는 무엇이 다르고, 그 사이에서 벌어지는 일을 무엇이라고 부를까요? 그리고 그렇게 만들어진 정보를 여러 사람이 오래 함께 쓰려면 어디에 어떻게 담아 두어야 할까요? — 이 질문에 답하는 것이 이번 편입니다.

M-Robo

삐빅 — 영수증은 데이터이고, "점심에 잘 팔린다"는 정보입니다, 휴먼. 같은 값에서 여러 정보가 나옵니다. 박사님, 정리 완료입니다.

조수실습·질문

박사설계 원리

01

데이터와 정보Data and Information

두 낱말은 자주 섞여 쓰이지만, 데이터베이스를 배울 때는 반드시 갈라 놓아야 합니다.

1정의
데이터현실에서 관찰하거나 측정해 수집한 값
정보데이터를 의사결정에 유용하게 활용할 수 있도록 처리해 체계적으로 조직한 결과물
한 줄 구분 데이터는 날것(raw), 정보는 쓸 수 있게 만든 것. 데이터는 그 자체로는 의사결정에 바로 쓸 수 없고, 정보는 바로 쓸 수 있습니다.
2비교
구분데이터정보
성격관찰·측정한 값가공·조직한 결과
예온도 31.2℃, 4,600원"폭염이다", "점심 매출이 늘었다"
의사결정그대로는 어려움바로 활용 가능
가공 횟수0회1회 이상
저장 위치데이터베이스보고서·대시보드·판단
3데이터 → 정보 단계 애니메이션
수집 → [ 1,400 · 1,400 · 1,800 ] 정리 → [ 삼각김밥 ×2, 아메리카노 ×1 ] 집계 → 합계 4,600원 해석 → "점심 직후 편의점 매출 발생"

아직 아무것도 하지 않은 상태입니다. 영수증에 찍힌 날것의 값만 있습니다.

수집 → [ 1,400 · 1,400 · 1,800 ] ← 이 단계 정리 → [ 삼각김밥 ×2, 아메리카노 ×1 ] 집계 → 합계 4,600원 해석 → "점심 직후 편의점 매출 발생"

수집: 같은 종류의 값을 한곳에 모읍니다. 아직 의미는 없지만 모으는 순간 비교가 가능해집니다.

수집 → [ 1,400 · 1,400 · 1,800 ] 정리 → [ 삼각김밥 ×2, 아메리카노 ×1 ] ← 이 단계 집계 → 합계 4,600원 해석 → "점심 직후 편의점 매출 발생"

정리: 값에 이름을 붙이고 묶습니다. 같은 상품을 하나로 합치면 개수라는 새 값이 생깁니다.

수집 → [ 1,400 · 1,400 · 1,800 ] 정리 → [ 삼각김밥 ×2, 아메리카노 ×1 ] 집계 → 합계 4,600원 ← 이 단계 해석 → "점심 직후 편의점 매출 발생"

집계: 더하고 세어 하나의 숫자로 만듭니다. 이 숫자는 원래 영수증 어디에도 없습니다.

수집 → [ 1,400 · 1,400 · 1,800 ] 정리 → [ 삼각김밥 ×2, 아메리카노 ×1 ] 집계 → 합계 4,600원 해석 → "점심 직후 편의점 매출 발생" ← 이 단계

해석: 숫자에 뜻을 붙입니다. 여기서부터 의사결정에 쓸 수 있는 정보가 됩니다 — "오후 3시에 삼각김밥 재고를 늘리자".

1 / 5
  • ① 원시 데이터 — 손대지 않은 값
  • ② 수집 — 비교할 수 있게 모으기
  • ③ 정리 — 이름 붙이고 묶기
  • ④ 집계 — 더하고 세기
  • ⑤ 해석 — 뜻을 붙여 정보로

같은 영수증에서 다섯 단계를 거쳐 정보가 만들어집니다.

02

정보처리와 정보시스템Information Processing · Information System

데이터가 정보가 되는 과정과, 그 과정을 조직 차원에서 떠받치는 시스템을 봅니다.

1정보처리
정보처리 = "데이터에서 정보를 추출하는 과정 또는 방법"

앞의 애니메이션에서 본 수집 → 정리 → 집계 → 해석이 곧 정보처리입니다. 사람이 손으로 해도 되고, 프로그램이 해도 됩니다. 중요한 것은 어떤 데이터를 어떤 순서로 처리할지를 정하는 일이 설계라는 점입니다.

데이터베이스 설계와의 연결 정보처리의 순서를 정하려면 "나중에 무엇을 물어볼 것인가"를 먼저 알아야 합니다. 그래서 설계는 질문을 먼저 적고 표를 나중에 그리는 순서로 진행합니다.
2정보시스템
정의조직 운영에 필요한 데이터를 수집해 저장해 뒀다가, 의사결정에 필요할 때 처리해 유용한 정보를 만들어 주는 수단

3경영정보 시스템

기업이라는 시스템의 관점에서, 경영시스템의 목표인 이익 창출을 위해 다른 하위 시스템이 효율적으로 작동하도록 지원하는 경영 지원 시스템입니다.

재고관리 시스템으로 보면 판매 데이터(데이터) → 재고 차감(처리) → "이 상품은 3일 뒤 품절"(정보) → 발주 결정(의사결정). 이 한 줄이 정보시스템이 하는 일의 전부입니다.

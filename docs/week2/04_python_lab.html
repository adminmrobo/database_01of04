실습 — 파이썬의 데이터 구조Python Data Structures

2주차 실습은 코랩에서 진행했습니다. 같은 데이터를 리스트 · 배열 · 데이터프레임 세 가지 그릇에 담아 보면, 왜 데이터베이스가 표(테이블)를 기본 단위로 삼는지가 자연스럽게 이해됩니다.

1세 그릇 비교
그릇생김새열 이름타입잘 맞는 일
리스트값을 순서대로 나열없음섞여도 됨한 종류 값의 나열
배열같은 타입을 격자로없음하나로 고정수치 계산
데이터프레임행 × 열 표있음열마다 다름데이터베이스 테이블과 같은 모양
데이터프레임 = 메모리 위의 테이블 열 이름과 열마다 다른 타입, 행 단위 레코드 — 데이터베이스 테이블과 거의 같은 구조입니다. 그래서 pandas.read_sql()로 조회 결과를 그대로 받아올 수 있습니다.
2같은 데이터, 세 가지 담기
# [1] 리스트 — 순서만 있고 열 이름이 없다
names = ["김철수", "이영희", "박민수"]
ages  = [34, 28, 41]

# [2] 넘파이 배열 — 같은 타입만, 계산에 강하다
import numpy as np
age_arr = np.array(ages)
print("평균 나이:", age_arr.mean())        # 34.33...

# [3] 데이터프레임 — 열 이름 + 열마다 다른 타입 = 테이블
import pandas as pd
df = pd.DataFrame({
    "name":  ["김철수", "이영희", "박민수"],   # 문자형 (명목변수)
    "age":   [34, 28, 41],                   # 정수형 (비율변수, 이산)
    "grade": ["VIP", "일반", "VIP"],          # 범주형 (명목변수)
    "score": [0.91, 0.77, 0.85],             # 실수형 (비율변수, 연속)
})
print(df.dtypes)      # 열마다 타입이 다르다
print(df.shape)       # (3, 4) — 3행 4열 = 3레코드 4속성

실행하면 object / int64 / object / float64가 나옵니다. 열마다 타입이 다르다는 점이 데이터프레임과 배열의 결정적 차이이고, 데이터베이스 테이블이 열마다 타입을 따로 정하는 이유이기도 합니다.

3질문을 코드로 옮기기
# 질문: VIP 고객 중 나이가 30 이상인 사람은?
vip_over_30 = df[(df["grade"] == "VIP") & (df["age"] >= 30)]
print(vip_over_30[["name", "age"]])

# 같은 질문을 SQL로 쓰면
# SELECT name, age FROM customer WHERE grade = 'VIP' AND age >= 30;

# 리스트로 직접 하면
result = []
for i in range(len(names)):
    if df["grade"][i] == "VIP" and ages[i] >= 30:
        result.append((names[i], ages[i]))
print(result)
3주차 예고 데이터프레임의 조건 필터가 곧 SQL의 WHERE입니다. 파일(리스트)로 직접 짜면 코드가 길어지고 구조가 바뀌면 전부 고쳐야 하지만, 표로 다루면 질문만 바꾸면 됩니다. — 이 차이가 3주차의 주제입니다.

G1언제 쓰나

손에 있는 데이터(엑셀·CSV·메모)를 데이터베이스로 옮기기 전에, 각 열이 어떤 유형인지 정리하고 표를 어떻게 나눌지 상의할 때 씁니다.

G2실행 순서
  1. 데이터 준비첫 줄이 열 이름인 CSV 또는 엑셀 파일을 준비합니다.
  2. 프롬프트 복사아래 내용을 복사해 [ ] 칸을 채웁니다.
  3. 붙여 넣고 요청AI 도우미에게 붙여 넣고 데이터도 함께 올립니다.
  4. 검증AI가 정한 유형을 6장의 기준(명목·순서·등간·비율)으로 다시 확인합니다.
G3프롬프트 전체
# 역할
너는 데이터베이스 설계를 가르치는 튜터이자 데이터 분류 전문가다.

# 배경
나는 아래 데이터를 데이터베이스로 옮기려고 한다. 먼저 각 열의 성격을 정리하고 싶다.
- 데이터: [파일 이름], 행 수 [ ], 열 수 [ ]
- 열 이름과 뜻: [예: name(고객 이름), age(나이), grade(등급), score(점수)]
- 이 데이터로 나중에 답하고 싶은 질문: [예: VIP 고객 중 30세 이상은 몇 명인가]
- 쓰는 DBMS: [MySQL 8.x / PostgreSQL 16 / 아직 모름]

# 하고 싶은 일 (해당하는 번호만 남긴다)
A. 열 유형 분류: 각 열을 명목/순서/등간/비율 중 하나로 분류하고, 이산형·연속형도 표시한다.
B. 저장 형태 분류: 각 열을 정형/반정형/비정형 중 하나로 분류한다.
C. 타입 제안: 각 열에 알맞은 데이터 타입(문자/정수/실수/날짜/불리언)과 길이를 제안한다.
D. 표 나누기 초안: 이 데이터를 몇 개의 테이블로 나눌지, 왜 그렇게 나누는지 제안한다.
E. 확인 질문 만들기: 이 데이터의 유형을 묻는 3지선다 문제 5개를 해설과 함께 만든다.

# 반드시 지킬 것
1. 분류의 근거를 한 줄씩 적는다. "왜 명목인가"를 값의 예와 함께 설명한다.
2. 절대 영점이 있는지 없는지를 근거로 등간/비율을 가른다.
3. 금액과 수량은 실수(float)가 아니라 정확한 수(decimal)로 저장할 것을 제안한다.
4. 날짜와 시간은 문자열이 아니라 날짜 타입으로 저장할 것을 제안한다.
5. 확실하지 않은 열은 "확인 필요"라고 표시하고, 무엇을 물어봐야 하는지 적는다.
6. 지어내지 않는다. 내가 준 데이터에 없는 열을 임의로 추가하지 않는다.
7. 주석과 설명은 한국어로, 입문자도 따라올 수 있게 쓴다.

# 답변 형식
1. 한 줄 요약 (몇 개 열, 어떤 문제가 보이는지)
2. 열별 분류 표 (열 이름 / 값 예 / 유형 / 이산·연속 / 저장 형태 / 제안 타입 / 근거)
3. 표를 나누는 초안과 이유 3~5줄
4. 주의할 점 (중복, 결측, 타입 혼입 신호)
5. 다음에 해 볼 일 2~3가지

# 데이터
[여기에 CSV의 첫 20행이나 열 설명을 붙여 넣는다]
G4라인별 해설
프롬프트 문장왜 필요한가
"이 데이터로 나중에 답하고 싶은 질문"질문을 먼저 적어야 표를 나누는 기준이 생깁니다. 설계는 질문에서 시작합니다.
"절대 영점이 있는지로 등간/비율을 가른다"가장 많이 틀리는 지점입니다. 온도·IQ를 비율로 잘못 분류하면 통계 해석이 무너집니다.
"금액은 decimal"부동소수점 오차로 합계가 1원 어긋나는 사고를 막습니다.
"지어내지 않는다"AI가 없는 열을 만들어 설계를 부풀리는 것을 막는 안전장치입니다.
G5흔한 오류와 해결
증상원인해결
등급을 비율변수라고 답함문자열 코드를 숫자로 바꿔 저장하는 관행 때문순서만 있는지 확인. 순서뿐이면 순서변수입니다.
전화번호를 정수형으로 제안값이 전부 숫자라서앞의 0이 사라지고 계산 대상이 아니므로 VARCHAR가 맞습니다.
열 목록에 없는 열이 생김AI의 추측"지어내지 않는다" 조항을 강조하고 원본 열 목록을 다시 붙입니다.
G6체크리스트
  • 모든 열에 값 예시가 하나씩 붙어 있는가
  • 금액·수량이 정확한 수 타입인가
  • 날짜·시간이 문자열로 남아 있지 않은가
  • 전화번호·우편번호처럼 앞자리 0이 의미 있는 열이 문자형인가
  • "확인 필요"로 표시된 열을 실제로 확인했는가
G7미니 과제
과제영수증 예시(도입 문제)의 값들을 열로 바꾸어 10행짜리 CSV를 직접 만들고, 위 프롬프트로 유형 분류를 받아 보세요. 그다음 "이 표를 두 개로 나눈다면 어떻게 나눌까"를 물어보면 3주차 중복 문제의 씨앗이 보입니다.
G1언제 쓰나

분류가 끝난 데이터를 실제로 담아 보는 단계입니다. 이번 편에서는 쇼핑몰 예제의 첫 테이블 customer만 만듭니다. 실행 환경은 MySQL 8.0 이상입니다.

G2실행 순서
  1. 데이터베이스 만들기문자 집합을 utf8mb4로 지정합니다.
  2. 테이블 만들기열마다 타입과 제약을 지정합니다.
  3. 값 넣기샘플 고객 3명을 넣습니다.
  4. 확인타입과 저장 결과를 확인합니다.
G3전체 코드
-- [1] 데이터베이스 만들기 (한글이 깨지지 않도록 utf8mb4)
CREATE DATABASE IF NOT EXISTS shop
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
USE shop;

-- [2] 고객 테이블 만들기
CREATE TABLE customer (
  customer_id INT          NOT NULL AUTO_INCREMENT,   -- 대리키: 자동 증가
  name        VARCHAR(30)  NOT NULL,                  -- 명목변수(문자)
  email       VARCHAR(120) NOT NULL,                  -- 명목변수(문자)
  phone       VARCHAR(20)  NULL,                      -- 숫자처럼 보여도 문자!
  address     VARCHAR(200) NULL,
  grade       VARCHAR(10)  NOT NULL DEFAULT '일반',    -- 명목변수(코드)
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (customer_id),
  UNIQUE KEY uq_customer_email (email),
  CONSTRAINT ck_customer_grade CHECK (grade IN ('VIP','일반','휴면'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- [3] 샘플 데이터
INSERT INTO customer (name, email, phone, address, grade) VALUES
 ('김철수', 'chulsoo@shop.com', '010-1234-5678', '서울시 마포구', 'VIP'),
 ('이영희', 'younghee@shop.com', '010-2222-3333', '부산시 해운대구', '일반'),
 ('박민수', 'minsoo@shop.com',  NULL,            '대전시 유성구',  '일반');

-- [4] 확인 — 열의 타입을 먼저 본다
DESCRIBE customer;
SELECT customer_id, name, phone, grade FROM customer;

-- [5] 유형별 집계 — 6장의 분류가 그대로 질의가 된다
SELECT grade, COUNT(*) AS 고객수
FROM customer
GROUP BY grade;
G4라인별 해설
줄설명
utf8mb4한글은 물론 이모지까지 저장 가능한 문자 집합입니다. 생략하면 한글이 깨질 수 있습니다.
AUTO_INCREMENT값을 넣지 않아도 1,2,3…으로 자동 증가합니다. 대리키를 만드는 가장 흔한 방법입니다.
phone VARCHAR(20)전화번호는 계산 대상이 아니고 앞의 0이 의미를 가지므로 문자형이 정답입니다.
CHECK (grade IN …)명목변수는 정해진 값만 들어오게 막아야 합니다. MySQL은 8.0.16부터 실제로 동작합니다.
UNIQUE KEY이메일이 중복 저장되지 않게 합니다. 데이터베이스가 통합 데이터를 지키는 장치입니다.
ENGINE=InnoDB트랜잭션과 외래키를 지원하는 스토리지 엔진입니다. 기본값이지만 명시하는 습관을 들입니다.
G5흔한 오류와 해결
오류 메시지원인해결
Incorrect string value: '\xEC\xA0\x9C…'문자 집합이 utf8(3바이트)로 되어 있음DB·테이블을 utf8mb4로 다시 만들고 접속 시 charset=utf8mb4 지정
ERROR 1062: Duplicate entry … for key 'uq_customer_email'같은 이메일을 두 번 넣음정상 동작입니다. INSERT … ON DUPLICATE KEY UPDATE로 갱신으로 바꿉니다.
ERROR 3819: Check constraint … is violatedgrade에 허용되지 않은 값을 넣음CHECK 목록에 값을 추가하거나 입력값을 고칩니다.
ERROR 1045: Access denied for user권한 또는 비밀번호 문제계정 권한을 확인하고 GRANT로 권한을 부여합니다.
G6체크리스트
  • 데이터베이스와 테이블의 문자 집합이 utf8mb4인가
  • 모든 열에 타입과 NULL 허용 여부를 정했는가
  • 기본키를 정했는가
  • 명목변수에 CHECK 또는 코드 테이블을 붙였는가
  • 한글 데이터를 실제로 넣어 깨지지 않는지 확인했는가
G7미니 과제
과제customer에 birth_date DATE를 추가하고, "20대 고객 수"를 구하는 쿼리를 써 보세요. TIMESTAMPDIFF(YEAR, birth_date, CURDATE())를 쓰면 됩니다. — 나이가 비율변수라서 뺄셈이 가능하다는 점을 확인해 보세요.
G1언제 쓰나

같은 customer 테이블을 PostgreSQL 16 이상에서 만듭니다. MySQL과 무엇이 다른지를 나란히 보는 것이 이 탭의 목적입니다.

G2실행 순서
  1. 스키마 만들기PostgreSQL은 데이터베이스 안에 스키마를 한 겹 더 둡니다.
  2. 테이블 만들기자동 증가는 IDENTITY로 씁니다.
  3. 값 넣기RETURNING으로 방금 들어간 값을 바로 받습니다.
  4. 확인\d+로 구조를 봅니다.
G3전체 코드
-- [1] 스키마 만들기 (MySQL의 '데이터베이스'와 비슷하지만 한 겹 더 안쪽)
CREATE SCHEMA IF NOT EXISTS shop;
SET search_path TO shop, public;   -- 이후 이름은 shop 안에서 찾는다

-- [2] 고객 테이블 (MySQL과 다른 부분에 주석을 달았다)
CREATE TABLE customer (
  customer_id integer      GENERATED ALWAYS AS IDENTITY,  -- [차이] AUTO_INCREMENT 대신
  name        varchar(30)  NOT NULL,
  email       varchar(120) NOT NULL,
  phone       varchar(20),                                -- 여기도 문자형
  address     varchar(200),
  grade       varchar(10)  NOT NULL DEFAULT '일반',
  created_at  timestamptz  NOT NULL DEFAULT now(),         -- [차이] DATETIME 대신 timestamptz
  CONSTRAINT pk_customer PRIMARY KEY (customer_id),
  CONSTRAINT uq_customer_email UNIQUE (email),
  CONSTRAINT ck_customer_grade CHECK (grade IN ('VIP','일반','휴면'))
);

-- [3] 샘플 데이터 + 방금 만들어진 키를 돌려받기
INSERT INTO customer (name, email, phone, address, grade) VALUES
 ('김철수', 'chulsoo@shop.com', '010-1234-5678', '서울시 마포구', 'VIP'),
 ('이영희', 'younghee@shop.com', '010-2222-3333', '부산시 해운대구', '일반'),
 ('박민수', 'minsoo@shop.com',  NULL,             '대전시 유성구',  '일반')
RETURNING customer_id, name;   -- [차이] MySQL에는 없는 기능

-- [4] 확인 — psql 전용 명령
-- \d+ customer

-- [5] 유형별 집계
SELECT grade, count(*) AS "고객수"
FROM customer
GROUP BY grade;

G1언제 쓰나

CSV로 받은 원시 데이터를 읽어 유형을 확인하고, 데이터베이스에 넣기 전에 정리할 때 씁니다. 실행 환경은 Python 3.11 이상입니다.

G2실행 순서
  1. 읽기CSV를 데이터프레임으로 읽습니다.
  2. 살펴보기행·열 수, 타입, 결측치를 확인합니다.
  3. 정리타입을 바로잡고 중복을 찾습니다.
  4. 저장정리된 표를 다시 CSV로 내보냅니다.
G3전체 코드
# -*- coding: utf-8 -*-
"""2주차 실습 — 데이터 유형 점검과 정리 (pandas)"""
import pandas as pd

# [1] 읽기 — CSV를 데이터프레임으로
df = pd.read_csv("customer_raw.csv", encoding="utf-8")
print("행·열:", df.shape)

# [2] 타입과 결측치 한 번에 보기
print(df.dtypes)          # 열마다 타입이 다르다 = 테이블의 속성 타입
print(df.isna().sum())    # 열별 결측치 개수

# [3] 타입 바로잡기 — 전화번호가 숫자로 읽혔다면 되돌린다
#     (앞자리 0이 사라지고, 계산 대상이 아니므로 문자형이 맞다)
df["phone"] = df["phone"].astype("string")

# [4] 날짜 열은 날짜 타입으로
df["created_at"] = pd.to_datetime(df["created_at"], errors="coerce")

# [5] 유형별 점검 — 명목변수에 허용값만 있는지
allowed = {"VIP", "일반", "휴면"}
bad = df.loc[~df["grade"].isin(allowed), "grade"].unique()
print("허용되지 않은 등급:", bad)      # 빈 배열이면 정상

# [6] 중복 점검 — 데이터베이스의 UNIQUE 제약이 막아 줄 값들
dup_email = df[df.duplicated("email", keep=False)]
print("이메일 중복 행:", len(dup_email))

# [7] 정리 결과 내보내기 (데이터베이스에 넣을 준비)
df.to_csv("customer_clean.csv", index=False, encoding="utf-8-sig")
print("저장 완료:", df.shape)
G4라인별 해설
줄설명
df.dtypes열별 타입을 봅니다. 여기서 object로 나오는 열이 문자형입니다.
astype("string")전화번호를 되돌립니다. 판다스의 string은 결측치를 <NA>로 다뤄 안전합니다.
pd.to_datetime(..., errors="coerce")날짜로 바꾸지 못한 값은 예외를 내지 않고 결측치로 만듭니다. 원본을 잃지 않고 문제 지점을 찾는 방법입니다.
isin(allowed)SQL의 CHECK (grade IN …)을 미리 흉내 내 봅니다. 넣기 전에 걸러 내면 오류 메시지를 덜 봅니다.
duplicated("email")UNIQUE 제약에 걸릴 행을 미리 찾습니다. 실무에서 가장 자주 쓰는 사전 점검입니다.
encoding="utf-8-sig"엑셀에서 열었을 때 한글이 깨지지 않도록 BOM을 붙여 저장합니다.

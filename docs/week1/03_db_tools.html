02

MySQL과 MariaDB — 한 뿌리에서 갈라진 두 갈래MySQL · MariaDB

이름이 비슷한 데는 이유가 있습니다. 실제로 같은 사람이 만든 같은 코드에서 출발했습니다.

1이름의 유래

MySQL의 창시자는 핀란드 출신의 마이클 "몬티" 비데니우스입니다. 그는 자기 딸 My의 이름을 따서 MySQL이라 이름 붙였습니다. MySQL은 1995년에 등장해 웹 서비스와 함께 빠르게 퍼졌습니다.

그런데 왜 갈라졌나 MySQL을 만든 회사(MySQL AB)는 Sun Microsystems에 인수되었고, 이어 Oracle이 Sun을 인수(2010년 완료)했습니다. MySQL의 원 개발자들은 이 흐름에 반대하며 2009년 MySQL 소스에서 갈라져 나온 새 프로젝트를 시작했고, 이번에는 다른 딸 Maria의 이름을 붙였습니다 — MariaDB입니다.
2실무에서 무엇이 다른가
MySQL vs MariaDB — 실무 체감 차이
항목MySQLMariaDB
관리 주체Oracle (상용 겸 오픈소스)커뮤니티 재단
호환성기본 SQL과 클라이언트 도구가 대부분 호환 — 실습 코드는 거의 그대로 실행됩니다
저장 엔진InnoDB 중심InnoDB · Aria 등 선택 폭 넓음
학습 자료압도적으로 많음MySQL 자료를 그대로 활용 가능
이 강의에서의 선택 배우는 단계에서는 둘 중 무엇을 써도 무방합니다. 코드 예제는 MySQL 기준으로 적고, MariaDB에서도 그대로 실행되도록 씁니다. 설치가 간편한 쪽을 고르세요.
03

PostgreSQL — 표준과 확장성PostgreSQL

대학 연구실에서 태어나 표준을 가장 충실히 따르는 데이터베이스입니다.

1출발은 캘리포니아 대학 버클리

PostgreSQL의 뿌리는 UC 버클리에서 개발된 POSTGRES입니다. 1996년에 SQL을 지원하며 PostgreSQL이라는 이름을 갖게 되었습니다. 공식 문서에도 "지금 PostgreSQL로 알려진 객체-관계형 DBMS는 버클리의 POSTGRES 패키지에서 파생되었다"고 적혀 있습니다.

04

Oracle과 SQLite — 양 끝의 두 도구Oracle · SQLite

가장 큰 도구와 가장 작은 도구를 나란히 봅니다. 이 둘을 알면 나머지 도구의 위치가 잡힙니다.

1Oracle — 기업용의 기준

SQL 관계형 데이터베이스가 상용 제품으로 자리 잡은 초창기부터 존재해 온 대표적인 상용(유료) DBMS입니다. 대규모 기업·금융·공공 시스템에서 오래 쓰여 왔습니다.

  • 강점 — 대규모 처리, 안정성, 장애 대응, 지원 체계
  • 대가 — 라이선스 비용, 전담 인력, 무거운 운영
  • 배우는 단계 — SQL 문법은 거의 같으므로 나중에 옮겨 가도 부담이 작습니다
2SQLite — 파일 하나가 데이터베이스

서버를 설치하지 않습니다. 파일 하나(.db)가 곧 데이터베이스이고, 프로그램 안에 라이브러리로 들어갑니다. 휴대폰 앱·브라우저·데스크톱 프로그램이 이 방식을 씁니다.

  • 설치·설정이 필요 없다 — 파일만 있으면 끝
  • 파이썬에 표준 라이브러리로 포함되어 있어 import sqlite3만 하면 바로 씁니다
  • 여러 사람이 동시에 쓰는 대규모 서비스에는 맞지 않습니다
연습용으로 최적 SQL을 처음 익힐 때는 SQLite가 가장 편합니다. 설치 없이 파일 하나로 시작하고, 익숙해지면 MySQL·PostgreSQL로 옮기면 됩니다. 문법이 거의 같습니다.
sqlite3로 테이블을 만들고 조회한 실행 화면
파이썬은 손, 데이터베이스는 창고 — 질의(SQL)와 결과로 이어집니다
05

파이썬과 데이터베이스는 어떻게 다른가Python vs Database

가장 많이 받는 질문입니다. 둘은 경쟁 관계가 아니라 역할이 다릅니다.

1언어와 창고
파이썬과 데이터베이스 — 무엇을 하는 도구인가
항목파이썬데이터베이스 (DBMS)
정체프로그래밍 언어데이터를 보관·보장하는 시스템
잘하는 일계산 · 자동화 · 분석 · 파일 처리저장 · 조회 · 동시 사용 · 규칙 강제
데이터가 사는 곳실행하는 동안 메모리에만프로그램을 꺼도 남아 있음
여러 명이 함께각자 자기 컴퓨터에서하나의 원본을 함께
규칙 강제사람이 코드로 직접 확인DBMS가 자동으로 거부
관계파이썬이 데이터베이스에 물어보고, 받은 결과로 계산·분석·출력합니다
한 줄로 파이썬은 손, 데이터베이스는 창고입니다. 손이 아무리 재주가 좋아도 창고 없이 재고를 관리할 수는 없습니다.
2파이썬에서 데이터베이스 쓰기 — 설치 없이 바로
# 표준 라이브러리 — 설치가 필요 없습니다
import sqlite3

# [1] 연결 — 파일이 없으면 새로 만들어집니다
con = sqlite3.connect("shop.db")
cur = con.cursor()

# [2] 테이블 만들기 — 열마다 형식과 규칙을 정합니다 (DDL)
cur.execute("""
CREATE TABLE IF NOT EXISTS customer (
    customer_id INTEGER PRIMARY KEY,   -- 기본키: 비어 있을 수 없다
    name        TEXT    NOT NULL,      -- 이름은 반드시 있어야 한다
    email       TEXT    UNIQUE         -- 같은 이메일은 하나만
)
""")

# [3] 값 넣기 — ? 자리에 값을 끼워 넣습니다 (SQL 인젝션 방지)
cur.execute("INSERT OR IGNORE INTO customer (name, email) VALUES (?, ?)",
            ("김철수", "a@shop.com"))
con.commit()                          # 커밋해야 실제로 저장됩니다

# [4] 물어보기 — 조건에 맞는 행만 가져옵니다 (DML)
cur.execute("SELECT customer_id, name FROM customer WHERE name = ?", ("김철수",))
for row in cur.fetchall():
    print(row)                        # (1, '김철수')

con.close()
두 가지를 눈여겨보세요 ① 규칙을 코드가 아니라 테이블에 적었습니다(PRIMARY KEY · NOT NULL · UNIQUE). 그래서 나중에 다른 프로그램이 값을 넣어도 규칙이 지켜집니다.
② 값을 ?로 넘겼습니다. 문자열을 직접 이어 붙이면 SQL 인젝션에 노출됩니다. 뒤에서 다시 다룹니다.

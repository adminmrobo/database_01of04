실습 예제 데이터베이스 — 쇼핑몰Running Example

주차가 이어질수록 같은 예제를 조금씩 키워 갑니다. 처음에는 그냥 "표"였던 것이 키와 제약을 가진 데이터베이스로 자랍니다.

customer 고객
  • customer_id PK
  • name
  • email UQ
  • phone
  • address
  • created_at
1 ──── N
orders 주문
  • order_id PK
  • customer_id FK
  • ordered_at
  • status
1 ──── N
order_item 주문상세
  • order_id PK,FK
  • product_id PK,FK
  • quantity
  • unit_price
N ──── 1
product 상품
  • product_id PK
  • name
  • category_id FK
  • price
  • stock
N ──── 1
category 카테고리
  • category_id PK
  • name UQ
왜 쇼핑몰인가 고객·주문·상품은 데이터 중복 문제(주소를 여러 곳에 저장), 종속성 문제(파일 구조가 바뀌면 프로그램 수정), 참조 무결성(없는 상품을 주문할 수 없다), 다대다 관계(주문과 상품)를 한 번에 보여 줍니다. 파일 시스템의 한계부터 관계 모델까지 같은 재료로 설명할 수 있는 예제입니다.
HOW

이렇게 보면 좋아요How to Use

1차례대로

각 편은 도입 문제 → 개념 → 표와 그림 → 확인 문제 → 코드 가이드 → 용어 사전 순서로 되어 있습니다. 도입 문제만 읽고 넘겨도 전체 흐름은 잡힙니다.

2버튼을 눌러서

확인 문제는 보기를 누르면 즉시 채점되고 해설이 뜹니다. 캐릭터의 표정 버튼, 코드의 복사 버튼, 탭으로 나뉜 코드 가이드도 모두 눌러 보세요.

3코드는 그대로

모든 코드 블록은 복사해서 바로 실행할 수 있습니다. MySQL·PostgreSQL·파이썬 세 갈래로 같은 설계를 보여 주니, 두 DBMS의 차이를 나란히 비교해 보세요.

4용어는 눌러서

본문에 점선 밑줄이 있는 낱말은 누르면 비유와 뜻이 뜹니다. 편마다 끝에 용어 사전이 있어 한꺼번에 훑을 수도 있습니다.

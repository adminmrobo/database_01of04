도입 문제 — 영수증 한 장Problem

오늘 오후 3시 12분, 편의점에서 삼각김밥 2개와 커피 1잔을 샀습니다. 영수증에는 이런 값들이 찍혀 있습니다.

가영수증에 찍힌 것
2026-10-18 15:12:07 삼각김밥 1,400 × 2 아메리카노 1,800 × 1 합계 4,600 카드 ****-1234

날짜, 시각, 상품명, 단가, 수량, 합계, 카드번호 — 모두 현실에서 관찰하거나 측정해 수집한 값입니다. 이것이 데이터입니다.

나여기서 무엇을 알 수 있나
  • 오늘 오후 3시대 매출은 4,600원이다.
  • 삼각김밥이 커피보다 많이 팔렸다(2개 vs 1개).
  • 이 카드 사용자는 점심 직후에 편의점을 자주 온다.

이 세 문장은 영수증에 직접 적혀 있지 않습니다. 값들을 모으고, 세고, 비교해서 만들어 낸 결과입니다. 이것이 정보입니다.

다그래서 이 편의 질문

데이터와 정보는 무엇이 다르고, 그 사이에서 벌어지는 일을 무엇이라고 부를까요? 그리고 그렇게 만들어진 정보를 여러 사람이 오래 함께 쓰려면 어디에 어떻게 담아 두어야 할까요? — 이 질문에 답하는 것이 이번 편입니다.

01

데이터와 정보Data and Information

두 낱말은 자주 섞여 쓰이지만, 데이터베이스를 배울 때는 반드시 갈라 놓아야 합니다.

1정의
데이터현실에서 관찰하거나 측정해 수집한 값
정보데이터를 의사결정에 유용하게 활용할 수 있도록 처리해 체계적으로 조직한 결과물
한 줄 구분 데이터는 날것(raw), 정보는 쓸 수 있게 만든 것. 데이터는 그 자체로는 의사결정에 바로 쓸 수 없고, 정보는 바로 쓸 수 있습니다.

정리: 값에 이름을 붙이고 묶습니다. 같은 상품을 하나로 합치면 개수라는 새 값이 생깁니다.

수집 → [ 1,400 · 1,400 · 1,800 ] 정리 → [ 삼각김밥 ×2, 아메리카노 ×1 ] 집계 → 합계 4,600원 ← 이 단계 해석 → "점심 직후 편의점 매출 발생"

집계: 더하고 세어 하나의 숫자로 만듭니다. 이 숫자는 원래 영수증 어디에도 없습니다.

수집 → [ 1,400 · 1,400 · 1,800 ] 정리 → [ 삼각김밥 ×2, 아메리카노 ×1 ] 집계 → 합계 4,600원 해석 → "점심 직후 편의점 매출 발생" ← 이 단계

해석: 숫자에 뜻을 붙입니다. 여기서부터 의사결정에 쓸 수 있는 정보가 됩니다 — "오후 3시에 삼각김밥 재고를 늘리자".

03

데이터베이스의 정의Definition of Database

데이터베이스는 "데이터를 모아 둔 것"이 아닙니다. 네 가지 조건을 모두 만족해야 데이터베이스라고 부릅니다.

1네 가지 데이터
공유 데이터여러 사용자가 함께 소유하고 이용하는 데이터
통합 데이터중복을 최소화해 허용하는 데이터 (통제 가능성)
저장 데이터컴퓨터가 접근할 수 있는 데이터
운영 데이터지속적으로 유지·관리되는 데이터
중복은 "없애는 것"이 아니라 "통제하는 것" 통합 데이터는 중복을 0으로 만드는 것이 아니라 허용하되 통제 가능한 수준으로 관리한다는 뜻입니다. 성능을 위해 일부러 중복을 남기는 설계(반정규화)도 이 조건 안에서 이루어집니다.
2하나씩 뜯어 보기
쇼핑몰 데이터베이스를 이 기준으로 검사하면
조건쇼핑몰에서는판정
공유고객·상품·주문 데이터를 여러 부서가 함께 조회○
통합고객 주소는 customer 한 곳에만, orders는 참조만○
저장디스크에 파일로 저장되어 SQL로 접근○
운영매일 새 주문이 쌓이고 상태가 바뀜○

네 조건이 모두 ○이어야 데이터베이스입니다. 엑셀 파일 하나를 부서별로 복사해 쓰는 것은 공유·통합에서 이미 어긋납니다.

04

데이터베이스의 특징Characteristics

네 문장으로 요약됩니다. 각 문장은 나중에 배울 기술과 하나씩 연결됩니다.

1실시간 접근

데이터베이스는 실시간 접근이 가능합니다. 요청한 순간의 값을 곧바로 돌려줍니다.

연결되는 기술인덱스와 질의처리기(4편). 밤에 배치로 돌리는 파일 처리와 갈리는 지점입니다.
2계속 변화

데이터베이스는 계속 변화합니다. 삽입·수정·삭제가 끊이지 않습니다.

연결되는 기술트랜잭션과 회복(12~13장). 변하는 도중에 사고가 나도 값을 지켜야 합니다.
3동시 공유

데이터베이스는 동시 공유가 가능합니다. 여러 사용자가 같은 순간에 같은 데이터를 다룹니다.

연결되는 기술동시성 제어와 잠금. 3편의 "동시 공유 기능 부족" 문제와 정확히 대응됩니다.
4내용으로 참조

데이터베이스는 내용으로 참조가 가능합니다. 주소(물리적 위치)가 아니라 값의 조건으로 찾습니다.

연결되는 기술SQL. "파일 3번째 블록"이 아니라 "이름이 김철수인 고객"이라고 묻습니다.

05

형태에 따른 데이터의 분류Structured · Semi-structured · Unstructured

데이터베이스가 다루는 대상은 표뿐이 아닙니다. 구조가 얼마나 미리 정해져 있는가로 세 갈래로 나눕니다.

1정형 데이터

미리 정해진 구조에 따라 저장된 데이터. 열의 이름과 타입이 처음부터 정해져 있습니다.

customer ┌────┬────────┬──────────────┐ │ id │ name │ email │ ← 구조 고정 ├────┼────────┼──────────────┤ │ 1 │ 김철수 │ a@shop.com │ │ 2 │ 이영희 │ b@shop.com │ └────┴────────┴──────────────┘

관계형 데이터베이스의 주 무대입니다.

2반정형 데이터

구조에 따라 저장된 데이터 + 데이터 안에 구조에 대한 설명이 존재. 값 자체가 자기 구조를 들고 다닙니다.

{ "name": "김철수", "tags": ["vip","서울"], "memo": null } ← 이름표를 스스로 가짐

JSON·XML·HTML이 대표적입니다. 열이 늘어도 스키마를 고치지 않습니다.

3비정형 데이터

정해진 구조가 없이 저장된 데이터. 안을 열어 보기 전에는 무엇이 들어 있는지 알 수 없습니다.

[ 사진.jpg ] [ 통화녹음.mp3 ] [ 계약서.pdf ] [ 로그.txt ] ← 구조 없음

텍스트·이미지·영상·음성. 별도 검색 기술이나 NoSQL과 함께 다룹니다.

4세 갈래를 한눈에
구분구조구조 설명의 위치대표 예주로 쓰는 저장소
정형미리 정해짐데이터 바깥(스키마)회원 명부, 주문 내역, 센서 수치관계형 DBMS (MySQL, PostgreSQL)
반정형데이터마다 다름데이터 안에 포함JSON, XML, HTML, 로그문서형 NoSQL, JSONB 열
비정형없음없음이미지, 음성, 영상, 자유 문서객체 스토리지 + 메타데이터 색인
실무에서는 섞어 씁니다 쇼핑몰에서도 고객·주문은 정형으로, 상품 상세 옵션은 JSONB 열로, 상품 이미지는 객체 스토리지에 두고 경로만 정형으로 저장합니다. 한 데이터베이스 안에서 세 형태가 공존하는 것이 보통입니다.

06

특성에 따른 데이터의 분류Categorical · Numerical

같은 표 안에서도 열마다 성격이 다릅니다. 이 구분이 나중에 데이터 타입과 제약 조건을 정하는 근거가 됩니다.

1큰 갈래 — 범주형 vs 수치형

범주형 자료는 질적 특성을 나타내는 자료로 개체를 분류하는 데 사용됩니다. 수치형 자료는 양적 특성을 나타내며 측정이나 계산이 가능한 값을 갖습니다. 범주형 자료는 통계적 분석에 제한이 있지만, 수치형 자료는 다양한 수학적 연산과 통계 분석이 가능합니다.

2네 가지 척도, 하나씩
변수할 수 있는 것예주의
명목같다/다르다 구분성별, 종교, 혈액형크기 비교 불가
순서구분 + 순서학력 수준, 만족도간격의 크기 측정 불가
등간순서 + 일정한 간격IQ, 섭씨 온도절대 영점이 없음
비율간격 + 비율 계산연령, 무게, 거리, 시간사칙연산 모두 가능
온도의 함정 섭씨 100도가 50도보다 "2배 뜨겁다"고 말할 수 없습니다. 0도가 "열이 없음"이 아니라 그냥 물이 어는 점이기 때문입니다. 절대 영점이 없으면 비율 계산이 불가능합니다. 켈빈으로 바꾸면 비율변수가 됩니다.
3이산형과 연속형
연속형시간에 대해 행동과 상태가 유한차원 벡터공간 — 주가 수익률, 자동차의 운행거리
이산형시간에 대해 행동과 상태가 원소 형태의 값을 갖는다 — {라이트를 켠다, 라이트를 끈다, 매도한다, 매수한다}
연속형 : 수익률 → 0.0127, 0.0131, ... (사이 값이 존재) 이산형 : 전원 상태 → ON / OFF (사이 값이 없음)
4이 분류가 설계에서 하는 일
분류DB 설계에서
명목VARCHAR + 코드 테이블(또는 ENUM). 정렬은 의미 없음
순서SMALLINT로 순위를 저장 + 코드 테이블에 순서값
등간·비율DECIMAL(금액·정확도 필요) 또는 DOUBLE(측정값)
이산INT 또는 BOOLEAN·ENUM
연속DECIMAL(p,s) — 소수 자릿수를 미리 정한다

금액에 FLOAT를 쓰면 0.1 + 0.2 문제로 합계가 어긋납니다. 금액은 언제나 DECIMAL입니다.

import pandas as pd
df = pd.DataFrame({
    "name":  ["김철수", "이영희", "박민수"],   # 문자형 (명목변수)
    "age":   [34, 28, 41],                   # 정수형 (비율변수, 이산)
    "grade": ["VIP", "일반", "VIP"],          # 범주형 (명목변수)
    "score": [0.91, 0.77, 0.85],             # 실수형 (비율변수, 연속)
})
print(df.dtypes)      # 열마다 타입이 다르다
print(df.shape)       # (3, 4) — 3행 4열 = 3레코드 4속성

# 리스트로 직접 하면
result = []
for i in range(len(names)):

G3프롬프트 전체
# 역할
너는 데이터베이스 설계를 가르치는 튜터이자 데이터 분류 전문가다.

# 배경
나는 아래 데이터를 데이터베이스로 옮기려고 한다. 먼저 각 열의 성격을 정리하고 싶다.
- 데이터: [파일 이름], 행 수 [ ], 열 수 [ ]
- 열 이름과 뜻: [예: name(고객 이름), age(나이), grade(등급), score(점수)]
- 이 데이터로 나중에 답하고 싶은 질문: [예: VIP 고객 중 30세 이상은 몇 명인가]
- 쓰는 DBMS: [MySQL 8.x / PostgreSQL 16 / 아직 모름]

# 하고 싶은 일 (해당하는 번호만 남긴다)
A. 열 유형 분류: 각 열을 명목/순서/등간/비율 중 하나로 분류하고, 이산형·연속형도 표시한다.
B. 저장 형태 분류: 각 열을 정형/반정형/비정형 중 하나로 분류한다.
C. 타입 제안: 각 열에 알맞은 데이터 타입(문자/정수/실수/날짜/불리언)과 길이를 제안한다.
D. 표 나누기 초안: 이 데이터를 몇 개의 테이블로 나눌지, 왜 그렇게 나누는지 제안한다.
E. 확인 질문 만들기: 이 데이터의 유형을 묻는 3지선다 문제 5개를 해설과 함께 만든다.

# 반드시 지킬 것
1. 분류의 근거를 한 줄씩 적는다. "왜 명목인가"를 값의 예와 함께 설명한다.
2. 절대 영점이 있는지 없는지를 근거로 등간/비율을 가른다.
3. 금액과 수량은 실수(float)가 아니라 정확한 수(decimal)로 저장할 것을 제안한다.
4. 날짜와 시간은 문자열이 아니라 날짜 타입으로 저장할 것을 제안한다.
5. 확실하지 않은 열은 "확인 필요"라고 표시하고, 무엇을 물어봐야 하는지 적는다.
6. 지어내지 않는다. 내가 준 데이터에 없는 열을 임의로 추가하지 않는다.
7. 주석과 설명은 한국어로, 입문자도 따라올 수 있게 쓴다.

# 답변 형식
1. 한 줄 요약 (몇 개 열, 어떤 문제가 보이는지)
2. 열별 분류 표 (열 이름 / 값 예 / 유형 / 이산·연속 / 저장 형태 / 제안 타입 / 근거)
3. 표를 나누는 초안과 이유 3~5줄
4. 주의할 점 (중복, 결측, 타입 혼입 신호)
5. 다음에 해 볼 일 2~3가지

G2실행 순서

  2. 테이블 만들기열마다 타입과 제약을 지정합니다.

G3전체 코드
-- [1] 데이터베이스 만들기 (한글이 깨지지 않도록 utf8mb4)
CREATE DATABASE IF NOT EXISTS shop
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
USE shop;

-- [2] 고객 테이블 만들기
CREATE TABLE customer (
  customer_id INT          NOT NULL AUTO_INCREMENT,   -- 대리키: 자동 증가
  name        VARCHAR(30)  NOT NULL,                  -- 명목변수(문자)
  email       VARCHAR(120) NOT NULL,                  -- 명목변수(문자)
  phone       VARCHAR(20)  NULL,                      -- 숫자처럼 보여도 문자!
  address     VARCHAR(200) NULL,
  grade       VARCHAR(10)  NOT NULL DEFAULT '일반',    -- 명목변수(코드)
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (customer_id),
  UNIQUE KEY uq_customer_email (email),
  CONSTRAINT ck_customer_grade CHECK (grade IN ('VIP','일반','휴면'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- [3] 샘플 데이터

-- [4] 확인 — 열의 타입을 먼저 본다
DESCRIBE customer;
SELECT customer_id, name, phone, grade FROM customer;

-- [5] 유형별 집계 — 6장의 분류가 그대로 질의가 된다

G4라인별 해설
줄설명
utf8mb4한글은 물론 이모지까지 저장 가능한 문자 집합입니다. 생략하면 한글이 깨질 수 있습니다.
AUTO_INCREMENT값을 넣지 않아도 1,2,3…으로 자동 증가합니다. 대리키를 만드는 가장 흔한 방법입니다.
phone VARCHAR(20)전화번호는 계산 대상이 아니고 앞의 0이 의미를 가지므로 문자형이 정답입니다.
CHECK (grade IN …)명목변수는 정해진 값만 들어오게 막아야 합니다. MySQL은 8.0.16부터 실제로 동작합니다.
UNIQUE KEY이메일이 중복 저장되지 않게 합니다. 데이터베이스가 통합 데이터를 지키는 장치입니다.
ENGINE=InnoDB트랜잭션과 외래키를 지원하는 스토리지 엔진입니다. 기본값이지만 명시하는 습관을 들입니다.

G6체크리스트
  • 데이터베이스와 테이블의 문자 집합이 utf8mb4인가
  • 모든 열에 타입과 NULL 허용 여부를 정했는가
  • 기본키를 정했는가
  • 명목변수에 CHECK 또는 코드 테이블을 붙였는가
  • 한글 데이터를 실제로 넣어 깨지지 않는지 확인했는가
G7미니 과제
과제customer에 birth_date DATE를 추가하고, "20대 고객 수"를 구하는 쿼리를 써 보세요. TIMESTAMPDIFF(YEAR, birth_date, CURDATE())를 쓰면 됩니다. — 나이가 비율변수라서 뺄셈이 가능하다는 점을 확인해 보세요.

G2실행 순서

  2. 테이블 만들기자동 증가는 IDENTITY로 씁니다.
  3. 값 넣기RETURNING으로 방금 들어간 값을 바로 받습니다.
  4. 확인\d+로 구조를 봅니다.

-- [2] 고객 테이블 (MySQL과 다른 부분에 주석을 달았다)
CREATE TABLE customer (
  customer_id integer      GENERATED ALWAYS AS IDENTITY,  -- [차이] AUTO_INCREMENT 대신

G1언제 쓰나

CSV로 받은 원시 데이터를 읽어 유형을 확인하고, 데이터베이스에 넣기 전에 정리할 때 씁니다. 실행 환경은 Python 3.11 이상입니다.

G2실행 순서
  1. 읽기CSV를 데이터프레임으로 읽습니다.
  2. 살펴보기행·열 수, 타입, 결측치를 확인합니다.
  3. 정리타입을 바로잡고 중복을 찾습니다.
  4. 저장정리된 표를 다시 CSV로 내보냅니다.
G3전체 코드
# -*- coding: utf-8 -*-
"""2주차 실습 — 데이터 유형 점검과 정리 (pandas)"""
import pandas as pd

# [1] 읽기 — CSV를 데이터프레임으로
df = pd.read_csv("customer_raw.csv", encoding="utf-8")
print("행·열:", df.shape)

# [2] 타입과 결측치 한 번에 보기
print(df.dtypes)          # 열마다 타입이 다르다 = 테이블의 속성 타입
print(df.isna().sum())    # 열별 결측치 개수

# [3] 타입 바로잡기 — 전화번호가 숫자로 읽혔다면 되돌린다
#     (앞자리 0이 사라지고, 계산 대상이 아니므로 문자형이 맞다)
df["phone"] = df["phone"].astype("string")

# [4] 날짜 열은 날짜 타입으로
df["created_at"] = pd.to_datetime(df["created_at"], errors="coerce")

# [5] 유형별 점검 — 명목변수에 허용값만 있는지
allowed = {"VIP", "일반", "휴면"}
bad = df.loc[~df["grade"].isin(allowed), "grade"].unique()
print("허용되지 않은 등급:", bad)      # 빈 배열이면 정상

# [6] 중복 점검 — 데이터베이스의 UNIQUE 제약이 막아 줄 값들
dup_email = df[df.duplicated("email", keep=False)]
print("이메일 중복 행:", len(dup_email))

# [7] 정리 결과 내보내기 (데이터베이스에 넣을 준비)
df.to_csv("customer_clean.csv", index=False, encoding="utf-8-sig")
print("저장 완료:", df.shape)
G4라인별 해설
줄설명
df.dtypes열별 타입을 봅니다. 여기서 object로 나오는 열이 문자형입니다.
astype("string")전화번호를 되돌립니다. 판다스의 string은 결측치를 <NA>로 다뤄 안전합니다.

isin(allowed)SQL의 CHECK (grade IN …)을 미리 흉내 내 봅니다. 넣기 전에 걸러 내면 오류 메시지를 덜 봅니다.
duplicated("email")UNIQUE 제약에 걸릴 행을 미리 찾습니다. 실무에서 가장 자주 쓰는 사전 점검입니다.
encoding="utf-8-sig"엑셀에서 열었을 때 한글이 깨지지 않도록 BOM을 붙여 저장합니다.

정보처리

정보시스템

비유주방 전체 — 재료를 사 오고, 보관하고, 조리해 내보내는 설비 일체.

뜻조직 운영에 필요한 데이터를 수집해 저장해 두었다가, 의사결정에 필요할 때 처리해 유용한 정보를 만들어 주는 수단.

데이터베이스의 조건

공유 데이터

비유사무실 공용 냉장고. 여러 사람이 함께 넣고 함께 꺼냅니다.

뜻여러 사용자가 함께 소유하고 이용하는 데이터.

통합 데이터

비유같은 우유를 냉장고 두 칸에 나눠 넣지 않기. 중복은 줄이되, 필요하면 한 칸에 두고 규칙으로 관리합니다.

뜻중복성을 최소화해서 허용하는 데이터. 통제 가능성이 핵심입니다.

저장 데이터

비유머릿속 레시피가 아니라, 종이에 적어 둔 레시피.

뜻컴퓨터가 접근할 수 있는 데이터.

운영 데이터

비유매일 갱신되는 재고 장부. 한 번 적고 끝나는 게 아닙니다.

뜻지속적으로 유지·관리되는 데이터.

데이터의 분류

정형 데이터

비유칸이 그려진 계란판. 어디에 무엇을 넣을지 이미 정해져 있습니다.

뜻미리 정해진 구조에 따라 저장된 데이터.

반정형 데이터

비유이름표를 달고 다니는 택배 상자. 겉에 내용물 이름이 적혀 있습니다.

뜻구조에 따라 저장된 데이터이면서 데이터 안에 구조에 대한 설명이 존재하는 데이터.

비정형 데이터

비유포장도 이름표도 없는 상자. 열어 봐야 압니다.

뜻정해진 구조가 없이 저장된 데이터.

명목변수

비유옷의 색 이름표. 빨강이 파랑보다 "크다"고 말할 수 없습니다.

뜻개체나 사람의 특성만 구분하는 변수(성별, 종교, 혈액형).

순서변수

비유달리기 순위. 1등이 2등보다 앞이지만, "두 배 빨랐다"고는 못 합니다.

뜻측정 대상 간 선호를 부여하는 변수(선호도, 만족도, 학력 수준).

등간변수

비유눈금이 일정한 자. 다만 0이 "없음"을 뜻하지는 않습니다.

뜻순서 + 값 사이의 간격이 일정한 변수(IQ, 섭씨 온도). 절대 영점이 없습니다.

비율변수

비유무게. 2kg은 1kg의 두 배라고 말할 수 있습니다.

뜻측정 대상 간에 비율 계산이 가능한 변수(연령, 무게, 거리, 시간).

이산형 · 연속형

비유계단식과 경사로. 계단은 중간에 설 수 없고, 경사로는 어디든 설 수 있습니다.

뜻이산형은 원소 형태의 값을(스위치 ON/OFF), 연속형은 유한차원 벡터공간의 값을 갖습니다(수익률, 운행거리).
